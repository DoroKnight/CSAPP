本目录包含构建和运行 CS:APP Bomb Lab 所需的文件。Bomb Lab 用于向
学生讲授机器级程序的原理，以及通用的调试和逆向工程技能。

***********
1. 概述
***********

----
1.1. 二进制炸弹
----
“二进制炸弹”是一个 Linux 可执行 C 程序，由六个“阶段”组成。每个
阶段都要求学生通过标准输入（stdin）输入一个特定字符串。如果学生
输入了预期的字符串，该阶段就会被“拆除”；否则，炸弹会打印
“BOOM!!!”并“爆炸”。学生的目标是拆除尽可能多的阶段。

----
1.2. 破解二进制炸弹
----
为了拆除炸弹，学生必须使用调试器（通常是 gdb 或 ddd）反汇编二进制
文件，并逐条执行每个阶段的机器代码。其核心是理解每条汇编语句的作用，
再据此推断出拆除炸弹所需的字符串。学生通过拆除阶段得分，而每次爆炸
都会被扣分（可由教师配置，通常扣 1/2 分）。因此，他们很快就会学会
在每个阶段以及引爆炸弹的函数之前设置断点。这是一项很有价值的练习，
能够促使学生真正掌握调试器的使用方法。

----
1.3. 自动评分服务
----
我们创建了一套独立运行的用户级自动评分服务，可替你处理 Bomb Lab 的
所有环节：学生从服务器下载自己的炸弹；在学生破解炸弹的过程中，每次
爆炸和拆除都会实时传回服务器；服务器则通过 Web“记分板”显示每个炸弹
的当前结果。实验不需要显式提交，并且会自动评分。

自动评分服务由四个运行在主目录 ./bomblab 中的用户级程序组成：

- 请求服务器（bomblab-requestd.pl）。学生在浏览器中访问一个名为
  “请求服务器”的简单 HTTP 服务器，以下载自己的炸弹并查看记分板。
  请求服务器会构建炸弹，将其归档为 tar 文件，再把生成的 tar 文件传回
  浏览器，供学生保存到磁盘并解包。请求服务器还会为教师保存一份炸弹
  及其解答。

- 结果服务器（bomblab-resultd.pl）。学生每拆除一个炸弹阶段或导致一次
  爆炸，炸弹都会向 HTTP“结果服务器”发送一条简短的 HTTP 消息，称为
  “自动结果字符串”（autoresult string）。结果服务器只是将该字符串
  追加到“记分板日志文件”中。

- 报告守护进程（bomblab-reportd.pl）。“报告守护进程”会定期扫描记分板
  日志文件，找出每名学生为每个阶段最近提交的拆除字符串，并将这些字符
  串应用于该学生炸弹的本地副本以进行验证。随后，它会更新 HTML 记分板；
  记分板汇总每个炸弹当前的爆炸和拆除次数，并按累计总分排序。

- 主守护进程（bomblab.pl）。“主守护进程”负责启动并监护请求服务器、
  结果服务器和报告守护进程，确保任意时刻上述每种进程（以及它自身）
  都恰好只有一个实例在运行。如果其中某个进程因故终止，主守护进程会
  检测到并自动重启它。实际需要手动运行的程序只有主守护进程。

2. 文件
********

*******************
3. 炸弹相关术语
*******************

LabID：每次开设的实验都由教师选择的唯一名称标识，例如“f12”或“s13”。
LabID 与当前实验不同的炸弹所产生的爆炸和拆除记录会被忽略。LabID 中不能
包含空格。

BombID：同一次实验中的每个炸弹都有一个唯一的非负整数编号，称为
“bombID”。

通知型炸弹（Notifying Bomb）：可以使用 NOTIFY 选项编译炸弹，使其在
学生引爆炸弹或拆除一个阶段时发送消息。这样的炸弹称为“通知型炸弹”。

静默型炸弹（Quiet Bomb）：如果使用 NONOTIFY 选项编译，炸弹在爆炸或
被拆除时不会发送任何消息。这样的炸弹称为“静默型炸弹”。

此外，区分定制炸弹和通用炸弹也很有帮助：

定制炸弹（Custom Bomb）：“定制炸弹”的 BombID > 0，与某一名特定学生
关联，并且既可以是通知型，也可以是静默型。定制通知型炸弹只能在教师
指定的一组 Linux 主机上运行；而定制静默型炸弹可以在任意 Linux 主机
上运行。

通用炸弹（Generic Bomb）：“通用炸弹”的 BombID = 0，不与任何特定学生
关联，并且属于静默型，因此可以在任意主机上运行。

************************
4. 开设 Bomb Lab
************************
Bomb Lab 有两种基本形式。在“在线”版本中，教师使用自动评分服务按需为
每名学生发放一个定制通知型炸弹，并通过实时记分板自动跟踪他们的进度。
在“离线”版本中，教师不使用自动评分服务，而是手动构建、发放并批改学生
的炸弹。

两种版本都能让学生获得丰富的学习体验，但我们推荐在线版本。它对学生
而言显然更有吸引力、更有趣，对教师而言评分也最方便。不过，它要求你
持续运行自动评分服务，因为实验期间的发放、评分和报告会连续进行。我们
已尽量简化该服务的运行方式，但部分教师可能不愿接受这一要求，因而会
选择离线版本。

下面分别介绍两种版本的开设方法。

---
4.1. 创建 Bomb Lab 目录
---
确定一台通用 Linux 机器（$SERVER_NAME），在其上创建 Bomb Lab 目录
（./bomblab）；如果开设在线版本，还要在该机器上运行自动评分服务。
你只需拥有该机器的普通用户账户，不需要 root 权限。

每次开设 Bomb Lab，都应从 $SERVER_NAME 上一个全新的 ./bomblab 目录
开始。例如：

    linux> tar xvf bomblab.tar
    linux> cd bomblab
    linux> make cleanallfiles

---
4.2. 配置 Bomb Lab
---
通过编辑以下文件配置 Bomb Lab：

./Bomblab.pm - 这是主配置文件。你只需修改或检查该文件第 1 节中的少量
变量。每个变量前都有说明性注释。如果开设离线版本，可以忽略其中大部分
设置。

如果开设在线版本，还需要编辑以下文件：

./src/config.h - 此文件列出了允许通知型炸弹在其上运行的主机域名。务必
正确更新该文件，否则你和学生都无法运行炸弹。

----
4.3. 更新实验讲义
---

更新配置文件后，请根据你的环境修改 ./writeup/bomblab.tex 中的 LaTeX
实验讲义。然后在 ./writeup 目录中输入：

	unix> make clean
	unix> make

这会创建讲义的 ps 和 pdf 版本。

---
4.4. 运行在线 Bomb Lab
---

------
4.4.1. 简要步骤
------
在 ./bomblab 目录中：

(1) 输入以下命令，从头重置 Bomb Lab：
    linux> make cleanallfiles

(2) 输入以下命令，启动自动评分服务：
    linux> make start

(3) 输入以下命令，停止自动评分服务：
    linux> make stop

你可以根据需要任意多次启动和停止自动评分服务，而不会丢失任何信息。
如果不确定该怎么做，执行“make stop; make start”可使所有组件恢复到
稳定状态。

但是，重置实验会删除所有旧炸弹、状态日志和记分板日志。只应在调试期间，
或第一次为学生启动实验时执行此操作。

学生通过浏览器访问以下地址申请炸弹：
    http://$SERVER_NAME:$REQUESTD_PORT/

学生通过浏览器访问以下地址查看记分板：
    http://$SERVER_NAME:$REQUESTD_PORT/scoreboard

------
4.4.2. 详细说明
------

(1) 重置 Bomb Lab。“make stop”确保没有服务器正在运行。
“make cleanallfiles”会从头重置实验，删除与某次具体实验相关的所有数据，
例如状态日志、请求服务器创建的所有炸弹以及记分板日志。当你准备好将
实验正式向学生开放时，请执行此操作。

在准备实验期间，重置也很有用。实验正式开放前，你可以为自己申请几个
炸弹，运行它们，拆除几个阶段、引爆几次，并确认结果正确显示在记分板上。
如果出现问题（例如忘记在 src/config.h 中更新允许炸弹运行的机器列表），
可以修正配置、重置实验，然后申请并运行更多测试炸弹。

注意：如果在实验正式开放后重置，你将丢失学生炸弹及其解答的全部记录，
无法验证学生的提交内容；学生也必须领取新炸弹并重新开始。

(2) 启动 Bomb Lab。“make start”会运行主守护进程 bomblab.pl。该进程会
启动并监护服务中的其他程序，每隔几秒检查一次它们的状态，并在必要时
重启它们。

(3) 停止 Bomb Lab。“make stop”会终止所有正在运行的服务器。你可以根据
需要任意多次启动和停止自动评分服务，而不会丢失任何信息。如果不确定，
执行“make stop; make start”可使所有组件恢复到稳定状态。

请求服务器（Request Server）：请求服务器是一个简单的专用 HTTP 服务器，
它会 (1) 按需构建定制炸弹并将其发送到学生的浏览器；(2) 显示实时记分板
的当前状态。

学生分两步向请求守护进程申请炸弹。首先，学生使用自己喜欢的浏览器访问：

    http://$SERVER_NAME:$REQUESTD_PORT/

例如 http://foo.cs.cmu.edu:15213/。请求服务器会向浏览器返回一个 HTML
表单。接着，学生在表单中填写用户名和电子邮件地址并提交。请求服务器
解析表单，构建 BombID=n 的定制通知型炸弹，将其打包为 tar 文件并发送
到浏览器。学生随后把 tar 文件保存到磁盘。解包后会创建一个目录
（./bomb<n>），其中包含以下四个文件：

    bomb*        定制通知型炸弹的可执行文件
    bomb.c       炸弹主例程的源代码
    ID           标识与此炸弹关联的学生
    README       列出炸弹编号、学生和电子邮件地址


请求服务器还会创建目录 bomblab/bombs/bomb<n>，其中包含以下文件：

    bomb*        定制炸弹的可执行文件
    bomb.c       主例程的源代码
    bomb-quiet*  用于自动评分的静默版炸弹
    ID           标识分配到此炸弹的用户名
    phases.c     炸弹各阶段的 C 源代码
    README       列出 bombID、用户名和电子邮件地址
    solution.txt 此炸弹的解答


结果服务器（Result Server）：每当学生拆除一个阶段或引爆炸弹时，炸弹
都会向结果服务器发送一条 HTTP 消息（称为自动结果字符串），结果服务器
再将该消息追加到记分板日志中。每条消息都包含 BombID、阶段以及所发生
事件的类型。如果事件是拆除，消息还会包含学生输入的“拆除字符串”。

报告守护进程（Report Daemon）：报告守护进程会定期扫描记分板日志并更新
Web 记分板。对于每个炸弹，它会统计爆炸次数和最近拆除的阶段，使用炸弹
的静默副本验证各个最近拆除的阶段，并在名为 scores.txt、以制表符分隔的
文本文件中计算每名学生的得分。更新频率是 Bomblab.pm 中的一个配置变量。

教师和学生可通过浏览器访问以下地址查看记分板：

    http://$SERVER_NAME:$REQUESTD_PORT/scoreboard

------
4.4.3. 在线 Bomb Lab 的评分
------
在线 Bomb Lab 会自动评分。在任意时刻，以制表符分隔的文件
（./bomblab/scores.txt）都包含每名学生的最新得分。报告守护进程每次生成
新记分板时都会创建此文件。

------
4.4.4. 在线 Bomb Lab 的补充说明
------
* 由于请求服务器和报告守护进程都需要执行炸弹，因此必须在
  bomblab/src/config.h 的合法机器列表中加入 $SERVER_NAME。

* 所有服务器和守护进程都是无状态的，因此可以任意多次停止
  （“make stop”）和启动（“make start”）实验，而不会产生不良影响。
  如果意外终止了某个守护进程、修改了某个守护进程，或某个守护进程因故
  退出，请先用“make stop”清理，再用“make start”重启。如果 Linux
  主机崩溃或重启，只需用“make start”重新启动这些守护进程。

* 来自服务器的信息和错误消息会追加到 bomblab/log-status.txt 中的
  “状态日志”。服务器以静默方式运行，因此可以通过 init.rc 脚本在启动
  系统时运行它们。

* 有关炸弹结构及构建方式的更多信息，请参阅 src/README。开设本实验并不
  要求理解这些内容；这里只是为了保证资料完整而提供。

* 在正式向学生开放实验前，我们通常会运行一些测试来检查所有组件。首先
  输入：

    linux> make cleanallfiles
    linux> make start

然后在 Web 浏览器中访问以下地址，为自己申请一个炸弹：

    http://$SERVER_NAME:$REQUESTD_PORT

将炸弹保存到磁盘后，解开其 tar 包，把它复制到 src/config.h 批准列表中
的一台主机上，然后引爆并拆除几次，以确认爆炸和拆除记录均正确出现在
记分板上。记分板的地址为：

    http://$SERVER_NAME:$REQUESTD_PORT/scoreboard

确认一切正常后，停止实验：

    linux> make stop

然后正式开放：

    linux> make cleanallfiles
    linux> make start

正式开放后，可以根据需要多次执行“make stop”和“make start”，但务必
不要再次执行“make cleanallfiles”。

----
4.5. 运行离线 Bomb Lab
----
在此版本中，你需要手动构建自己的静默型炸弹，再把它们发给学生。学生
离线完成炸弹拆除（即不依赖任何自动评分服务），然后将解答文件提交给你，
由你逐一手动评分。

可以使用 makebomb.pl 脚本手动构建炸弹。makebomb.pl 还会生成炸弹的解答。
输入“./makebomb.pl -h”可查看其参数。

方案 1：开设离线 Bomb Lab 最简单的方式是构建一个通用炸弹，由所有学生
尝试拆除：

    linux> ./makebomb.pl -s ./src -b ./bombs

这会在 ./bombs/bomb0 中创建一个通用炸弹以及其他一些文件：

    bomb*        通用炸弹的可执行文件（发给学生）
    bomb.c       主例程的源代码（发给学生）
    bomb-quiet*  忽略此文件
    ID           忽略此文件
    phases.c     炸弹各阶段的 C 源代码
    README       忽略此文件
    solution.txt 此炸弹的解答

只需将其中两个文件发给学生：./bomb 和 ./bomb.c。

学生会提交自己的解答文件，你可以将其输入炸弹进行验证：

    linux> cd bombs/bomb0
    linux> ./bomb < student_solution.txt

此方案对教师来说很方便，但我们不推荐，因为学生太容易作弊。

方案 2：开设离线实验的另一种方式是使用 makebomb.pl 脚本，为每名学生
构建一个独一无二的定制静默型炸弹：

    linux> ./makebomb.pl -i <n> -s ./src -b ./bombs -l bomblab -u <email> -v <uid>

这会在 ./bombs/bomb<n> 中为电子邮件地址为 <email>、用户名为 <uid> 的
学生创建一个定制静默型炸弹：

    bomb*        定制炸弹的可执行文件（发给学生）
    bomb.c       主例程的源代码（发给学生）
    bomb-quiet*  忽略此文件
    ID           标识与此炸弹关联的学生
    phases.c     炸弹各阶段的 C 源代码
    README       列出炸弹编号、学生和电子邮件地址
    solution.txt 此炸弹的解答

需要将其中四个文件发给学生：bomb、bomb.c、ID 和 README。

每名学生都会提交自己的解答文件。你可以运行其定制炸弹，并将解答文件
作为输入来手动验证：

    linux> cd ./bombs/bomb<n>
    linux> ./bomb < student_n_solution.txt

不同阶段变体的源代码位于 ./src/phases/ 中。
